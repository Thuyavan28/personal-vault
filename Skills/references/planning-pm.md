# Planning & Project Management

- **Break work down**: Epic → Feature → User story → Task. A task should be completable in under a day; if not, split it further.
- **Estimate honestly**: use ranges or story points, not false-precision hours. Flag unknowns explicitly ("spike needed") rather than guessing.
- **Definition of Done**: every task needs explicit acceptance criteria before work starts — what "done" means, including tests and docs, not just "code written."
- **Prioritization frameworks**: MoSCoW (Must/Should/Could/Won't), RICE (Reach/Impact/Confidence/Effort), Eisenhower matrix (urgent vs important).
- **Risk register**: for non-trivial projects, track top risks with likelihood, impact, and mitigation — don't just track tasks.
- **Dependencies**: map what blocks what before committing to a timeline; call out external dependencies (APIs, other teams, approvals) early.
- **Communicate scope changes**: if implementation reveals the ask was bigger/smaller than planned, say so immediately rather than silently absorbing it.
- **Agile ceremonies** (when relevant): standups (status + blockers, not a status report to a manager), sprint planning (commit to a sprint goal, not just a task list), retros (what to keep/stop/start).
